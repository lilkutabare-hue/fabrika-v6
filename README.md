# fabrika-v6 — сайт производства fabrika.market

Собрано 07.10.2026 по `../fabrika-PLAN.md` (этапы 0–8 одним заходом, по решениям раздела 13 «по умолчанию»). Старая витрина `../fabrika-vitrina.html` не тронута.

## Запуск

```bash
cd fabrika-v6 && python3 tools/serve.py 4180
```

Открыть `http://localhost:4180/`. Модулям и `fetch` нужен http, с `file://` не работает. Порты 5173 и 4188 заняты другими проектами.

Снимки экранов: `node tools/shots.mjs <папка>` — 1440×900 и 375×812 по разделам и слоям (headless Chromium из кэша Playwright, без библиотек). Готовые лежат в `shots/`.

Картинки: `python3 tools/build_media.py` — читает `data/media-map.json`, пишет WebP в `media/` и `media/manifest.json`. Исходные рендеры не трогает.

## Артефакт для показа

https://claude.ai/artifact/As8G3EtpEnFuxX6k4NEFEM — отдельный артефакт «Фабрика v6» (07.10). Старый «Витрина Фабрики» с его базой не тронут. Сборка для артефакта: `python3 tools/pack_artifact.py` → `dist/` (страница без своего каркаса, медиа только 600/1200 и родная ширина обрезки, без анимаций). Публикуется двумя порциями: код + половина картинок, затем остальные. База артефакта: `products` и `settings` читают все, пишет владелец; `orders` пишут и читают вошедшие в claude.ai (строже сервер не разрешает), гости без входа отправляют заявку только в Telegram. `assets` не объявлены: с ними артефакт нельзя открыть по внешней ссылке, поэтому загрузка картинок в админке там недоступна.

Правило роста: новый метод — запись в `methods.json`; новое поле товара — необязательное поле в `catalog.json` (читают `catalog.js` и `product.js`: `composition`, `fabric`, `fit`, `heights`, `sizeChart`, `shipDays`, `stock`, `makeDays`, `priceTiers`, `zoneCm`); новый способ отправки заявки — `addSender()` в `order.js`.

## Заявка

Объект по схеме плана §9.3: `v, id, createdAt, items[{product, color, size, gram, qty, unitPrice, prints[{method, film, side, place, width_mm, height_mm, offset_mm, scale_pct, allow_rotate, file{name,type,px,hasAlpha,dpi,kept}, checks[], priceFrom}]}], sewing, totals, contact, delivery, deadline, comment`.

Текст для Telegram строится из объекта. Кнопка: `t.me/<бот>?start=<id>`, если в настройках задан бот; иначе `t.me/<менеджер>?text=…`. Рядом «Скопировать». В артефакте заявка пишется в `orders` (`code, text, status, createdAt, total, data`). Файл макета живёт в памяти (`fileStore`) до появления сервера бота.

Поле печати — вся вещь: макет двигается и растёт по всему силуэту, «расположения» — пресеты (грудь, центр, рукава, карман, низ, спина, капюшон по типам). В заявку идёт `center` (центр макета в долях вещи) и `scale_pct` (ширина от ширины вещи). `width_mm` и `offset_mm` заполняются, когда у товара есть `widthCm` — реальная ширина вещи на рендере в сантиметрах: число (`"widthCm": 60`) или по размерам (`"widthCm": { "S": 56, "M": 60, "L": 64 }`). Пока его нет — «размер уточнит менеджер».

## Конструктор, волны 1–2 (08.10)

План в `CONSTRUCTOR-PLAN.md`. Сделано по решениям владельца («+» для ещё одной вещи в заказ, макет только менеджеру, цены позже):

- **Сцена.** Складки ткани: карта смещения считается из яркости рендера (canvas, кэш на кадр) и подаётся в SVG-фильтр `feDisplacementMap` на тело макета; во время движения фильтр снят. Поворот ручкой над макетом с примагничиванием к 0/45/90°, зеркало, щипок и поворот двумя пальцами на телефоне, ручка размера от центра. Колесо и щипок на пустом месте приближают вещь до 3×, перетаскивание двигает, двойной тап возвращает. Стрелки двигают на 1 % (Shift — 5 %), ⌘Z / ⇧⌘Z — отмена и повтор; стек на 60 шагов. Кнопка «Без принта» прячет макет, пока держишь.
- **Панель.** Сверху вещь, цена с методом, переключатель «Чистый бланк / С принтом». В режиме принта три вкладки: Макет (файл, проверка, отразить, выровнять, складки, убрать, примерить на другой вещи) · Где и как (пресеты картинками вещи с точкой, размер, методы карточками с макетом в каждом методе на цвете ткани) · Вещь (цвет, плотность, размер). Внизу липкая строка: количество, «В корзину», «+».
- **«+».** Кладёт вещь в корзину и предлагает выбрать следующую с тем же макетом. Под кнопками строка «В заказе N вещей · Оформить».
- **Телефон.** Сцена 58 svh с инструментами поверх, панель под ней, строка покупки прилипает к низу. Жесты на макете: один палец тянет, два — размер и поворот.
- В заявку добавлены `rotate_deg` и `mirrored`.

Не сделано из плана: волна 3 (слои на одной вещи, текст) отложена по решению владельца, волна 4 ждёт правила цен и ширину вещей.

## Воркер: заявка → DTF-раскладка → чат заказов (08.10)

`worker/worker.py` + `worker/README.md`. Сайт после «Отправить» шлёт на сервер (адрес в `settings.api`) заявку, текст, исходники макетов и картинки вещей с макетом (`app/print/mockup.js`, canvas: вещь, макет по месту с поворотом и зеркалом, обрезка по силуэту, тени ткани; клиенту не отдаётся). Воркер пишет в чат заказов текст и картинки, затем строит DTF-лист инструментом dtf-roll из скилла `xtc-dtf` по его правилам (ширина 570, поля 5, зазор 5, 150/220 dpi, чистка кромок, QC fail-closed): превью, `production.pdf`, `QC_REPORT.txt`. Макет на плёнке повёрнут и отражён так же, как на вещи. Плёнки и вышивка в лист не идут, уходят отдельным сообщением. Без размера в мм воркер просит менеджера: `/size <ID> <№> <мм>`. В `dtf_roll.py` добавлен параметр `DTF_ROLL_WIDTH` (по умолчанию 580). Проверено локально в сухом режиме: заявка с сайта → inbox → лист PASS 570×75 мм с повёрнутым макетом. Telegram-часть ждёт `BOT_TOKEN` и `CHAT_ID`.

## Слово владельца 07.10, после первого показа

- **Рендеры бланков — временные.** Набор `fabrika_cards_1400_normalized` и `новые рендеры` владелец назвал неактуальным: на сайте они только как заглушки, чтобы собрать и проверить механику. Актуальные фото придут отдельно; замена — через `data/media-map.json` и `tools/build_media.py`, код не трогается.
- **Экран 16:9 с айдентикой производства.** Слот стоит в блоке «Производство и шоурум» (`settings.factoryMedia`), три варианта раскадровки — в `HERO-16x9.md`.
- **Реестр нанесений.** Владелец пришлёт полный список того, что делает производство; каждая позиция — запись в `data/methods.json` (проверено на пробном методе без цены: встаёт в оба списка и в заявку без правки разметки).

- **Фон белый.** Серый тон под вещами убран: `--tone` = `#FFFFFF`, подложек у плиток, сцены, превью и схем нет.
- **Без гифок и видео.** Анимированные WebP-рендеры собраны в `media/`, но выключены флагом `ANIM_RENDERS` в `app/garment.js`. Движение только CSS.
- **Размер и расположение принта** подняты сразу под макет (макет → расположение → размер → метод). На самом макете угловая ручка: тянешь — меняется размер; ползунок в панели синхронен.
- **Принт по всей вещи (07.10, второй показ).** Оранжевой рамки нет: макет тянется и растёт по всему силуэту, в том числе на рукав и карман; пресеты расположений — быстрые позиции. Размер до 90 % ширины вещи.
- **Принт ложится по силуэту (08.10).** Слой макета обрезан маской по альфе рендера (у эскизов — по контуру SVG), поверх макета полупрозрачная копия вещи: складки и тени читаются сквозь принт, на тёмной ткани копия осветляется до серого. Большой макет больше не висит квадратом над вещью. Выбор цвета плёнки убран: в примерке плёнка контрастная к ткани, цвет подбирает менеджер.
- **Меньше интерфейса, Apple 2027.** Кнопки-пилюли строчными, переключатели как в iOS, категории чипсами, образцы цвета кругами, поля с мягкой заливкой, без подчёркиваний.
- **Косметика «дороже»:** воздух между блоками 88–96 px, эскизы тоньше, вещь на первом экране крупнее, в карточке одна кнопка закрытия, уведомление «Добавлено» ведёт в корзину. Линейные рисунки лекал и машинки убраны: превью пошива — чистая вещь со спины, кадр цеха ждёт файл.

- Путь «файл → макет на вещи → метод → в корзину → заявка → текст для Telegram» — проходит; плёнка даёт силуэт, вышивка — фактуру нити и проявление построчно; JPEG и многоцветный файл для плёнки дают подсказки, заявку не блокируют.

- Вес первого экрана на телефоне: HTML 17 КБ + CSS 54 + JS 124 + данные 38 + рендер худи 221 КБ (1058 px для DPR 3) + шрифты Google ≈ 530 КБ. На DPR 2 рендер 81 КБ (600 px).
