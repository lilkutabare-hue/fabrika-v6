# Воркер заявок: сайт → DTF-раскладка → чат заказов

Один файл `worker.py`, стандартная библиотека Python 3.12 плюс venv инструмента dtf-roll из скилла `xtc-dtf`.

## Что происходит

1. Клиент нажимает «Отправить в Telegram» на сайте. Сайт шлёт на воркер заявку (JSON по схеме плана §9.3), текст заявки, исходники макетов и картинки вещей с макетом, а клиенту открывает Telegram как раньше.
2. Воркер кладёт заявку в `inbox/<ID>/` и пишет в чат заказов: текст заявки, картинку каждой вещи с макетом (мокап для менеджера), исходники.
3. Для принтов, у которых метод с `prep: dtf-roll`, строится манифест и запускается `dtf-roll build` с правилами скилла: ширина `ROLL_WIDTH` (570), поля 5, зазор 5, 150/220 dpi, чистка кромок, QC с отказом. В чат уходят: статус PASS или BLOCKED, превью листа, `production.pdf` (1:1, не зеркалить), `QC_REPORT.txt`.
4. Плёнки и вышивка (`prep: plotter`, `embroidery`) в лист не кладутся: их файлы с размером уходят отдельным сообщением.
5. Если размера в мм нет (у товара не задан `widthCm`), воркер просит менеджера: `/size <ID> <№ принта> <мм>` в чате, после этого пересобирает. `/redo <ID>` пересобирает заново.
6. Клиент, открывший бота по ссылке `t.me/<бот>?start=<ID>`, получает подтверждение и может дослать файл: он сохранится в `inbox/<ID>/client-…`, менеджер увидит сообщение.

## Запуск

```bash
cd fabrika-v6/worker
cp .env.example .env     # вписать BOT_TOKEN и CHAT_ID
python3 worker.py
```

`BOT_TOKEN` — от @BotFather. `CHAT_ID` — id чата заказов (добавить бота в чат, написать в нём, взять `chat.id` из `getUpdates`). Без токена воркер работает в сухом режиме: раскладка строится, сообщения пишутся в `inbox/_outbox/`.

На сайте адрес воркера задаётся в настройках: `settings.api` в `data/catalog.json` (или поле «Сервер заявок» в админке артефакта), например `https://orders.fabrika.market`. Нужен https и доступ из браузера (CORS воркер отдаёт сам). Внутри артефакта claude.ai чужие адреса заблокированы, там работает только Telegram-путь.

Проверка руками:

```bash
curl -s http://127.0.0.1:4190/health
curl -s -F 'order=@../tools/sample-order.json;type=application/json' -F 'text=Проверка' -F 'file:abc123=@../tools/test-logo.png' http://127.0.0.1:4190/api/orders
python3 worker.py redo <ID>     # пересобрать лист из inbox без бота
```

## dtf-roll

Путь `DTF_ROLL` (по умолчанию `~/.claude/skills/xtc-dtf/reference/dtf-roll`). В `dtf_roll.py` добавлен параметр `DTF_ROLL_WIDTH` (по умолчанию 580, как в оригинале; воркер передаёт `ROLL_WIDTH`). Если venv сломан (`libmupdf.dylib` не найден): `uv pip install --python .venv/bin/python --reinstall pymupdf`.

Проверка `qc-sheet.py` из скилла к листу воркера не подходит: она считает dpi от ширины страницы, а не от рамки принта (в `QC_REPORT.txt` dtf-roll даёт честные effective dpi по каждому принту).

Что воркер пока не делает из скилла и делает менеджер: раздельные листы по краске и вектор для белого (правило XTC для своих тиражей), дозаправка готового рулона, цветокоррекция под печатника. Это следующий шаг, когда появятся реальные заказы.
